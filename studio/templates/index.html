      STL-1 / VGGT MULTI-RING VALIDATION

      One training ring and two held-out test rings

      Validation report Refinement report

      Each score excludes the target point map from reprojection. VGGT cameras are still inferred jointly from all five images, so this is a leave-one-surface-out diagnostic rather than a strict target-image holdout.

      PHASE 3 / CAMERA SEMANTIC DIAGNOSTIC

      Named-view priors and camera-snap experiment

      Prior report Snap report

      The named front, top and side axes are useful diagnostics, but they are not calibrated cameras. Snapping VGGT rotations directly to those axes reduced cross-view agreement, so the candidate was rejected.

      PHASE 3 / VGGT RESOLUTION LADDER

      Held-out resolution and view-transfer validation

      Resolution report View-transfer report

      The 518 px setting was selected from a 224–518 px ladder using three validation-split rings, then extended to all three test rings. It improves projected surface evidence substantially, but it still fails the Phase 3 geometry gate and remains non-metric research evidence.

      PHASE 3 / SILHOUETTE COMPLETION

      Four-view camera-space visual hull

      Completion report

      The target silhouette is excluded while the other four silhouettes are intersected using VGGT camera hypotheses. This improves outer-shape completion, but filled silhouettes do not reconstruct local relief, holes, cavities or editable CAD topology.

      PHASE 3 / SURFACE-AWARE CARVING

      Visible surfaces constrained inside the visual hull

      Surface report

      Voxels must satisfy all four source silhouettes and remain near a source-view VGGT surface. This restores more negative space and improves the weakest views, but inferred openings and internal topology are still uncertain.

      PHASE 3 / SIGNED-DEPTH CARVING

      Source-view free-space constraints

      Depth-carving report

      Voxels clearly in front of source-view VGGT surfaces are removed. One source contradiction is permitted because reflective, independently rendered views are not perfectly consistent. The rule is selected only on validation rings.

      PHASE 3 / PROJECTION NOISE

      Fragment-gated silhouette cleanup

      Noise report

      The visible scan-line gaps came from projecting a coarse voxel lattice, not widespread disconnected 3D geometry. A validation-selected 3×3 close is applied only when the raw projection contains at least four foreground components. It improves every test ring without regressing a test view, but changes only the review renderer—not the signed-depth voxels.

      PHASE 3 / REJECTED NORMAL EXPERIMENT

      Source-view normal consistency

      Normal report

      World-space normal hypotheses were derived from VGGT point-map tangents. Validation selected zero carving because every non-zero threshold reduced mean IoU, so signed depth remains the active baseline.

      PHASE 3 / NEGATIVE-SPACE EXPERIMENT

      Structural aperture preservation

      Aperture report

      Large enclosed source-mask regions were expanded before carving. The weakest test view improved, but mean held-out IoU fell, so this is retained only as component evidence and is not the default geometry path.

      PHASE 3 / REJECTED CAMERA EXPERIMENT

      Source-camera image-plane alignment

      Camera-alignment report

      Bounded translation and scale corrections were fitted from source views only. Validation retained the original VGGT cameras because every non-identity profile reduced held-out reconstruction agreement. This is evidence that the remaining error is not a simple 2D camera offset.

      PHASE 3 / REJECTED RIGID REGISTRATION

      Source point-map registration

      Rigid-registration report

      Each source point map and camera were transformed together with bounded SE(3) corrections while the held-out target remained excluded. ICP reduced nearest-neighbour cloud distance but progressively damaged reconstruction IoU, so validation retained the original VGGT geometry.

      PHASE 3 / LEARNED TRACK EXPERIMENT

      VGGT feature tracks and source registration

      Track report Registration report Dense-track report Cycle report

      The pinned VGGT track head first generated 96 and then 384 cross-view queries per view for seven rings within the 4 GB GPU limit. Bounds and source-query checks passed, but the tracks are not ground truth. Sparse registration lost 0.0024 test IoU. With four-times denser reciprocal tracks, every moving profile reduced validation IoU, so validation selected identity. Track evidence is retained for future component relationships, not for moving the current geometry.
